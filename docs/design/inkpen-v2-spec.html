01设计目标

一句话：让人不假思索地找到「写什么、机器在哪、怎么开写」，并且永远不会点错按钮。

① 频率分层，而不是功能平铺按使用频次把一个功能放到正确的层级：常驻 / 页签 / 折叠。原来的六页签把 Jog、DRO、连接、书写任务和「电机方向」「G 代码模板」放在同一权重上，是最大的可用性问题。
② 状态必须显性GRBL 有 8 个状态（Idle/Run/Hold/Jog/Alarm/Door/Home/Sleep），用户第一步永远是「机器现在能干什么」。状态放在顶栏常驻，颜色语义固定，可用性由状态决定而不是靠用户记忆。
③ 一个设置只有一个入口同一件事不在两处出现。「画布显示格线」曾经同时在左栏和工具条上；「连接」同时在顶栏和右栏。重复即歧义。
④ 破坏性动作只有一个是红的红色留给急停。停止、断开、清空都用中性色——红按钮一多，红就失效了。

02信息架构

三栏对应三个问题，顺序就是操作顺序：左栏决定写什么，中栏看写成什么样，右栏控制怎么写。

关键位移：从页签到常驻

GRBL 生态（gSender、Candle、UGS、LaserGRBL）虽然界面各不相同，但五块信息是共同的：端口连接、DRO、Jog、路径预览、控制台。老手的肌肉记忆全落在这五块上。所以新方案不发明交互，只做位置重排：

04栅格与响应

基准窗口 1280 × 800，最小可用 1180 × 700。三栏固定 + 中栏弹性，中栏永远先让位。

断点左 / 中 / 右行为
≥ 1280292 / 1fr / 344完整三栏，画布居中留白 16
1100 – 1279264 / 1fr / 320两栏同步收窄；Jog 键 40 → 36；画布降到 45% 缩放
900 – 1099240 / 1fr / 56右栏折叠成图标条，点开浮层（此时不推荐书写任务）
高度 < 740—左栏隐藏文稿输入区，只留版式；中栏画布优先

右栏宽度是算出来的：3×轴卡片 101 + 2×间距 6 + 内边距 28 = 344。左栏是 278 内容 + 2×12 内边距 = 302 收 10px 取整 292。改宽度先改这两个式子，不要拍脑袋。

05组件库

按钮 · 四型四态

高度 28（默认）/ 30（工具栏）/ 36（主操作）。图标全部 16×16 手绘矢量，与文字间距 6。悬停只改背景与描边，不做位移——机床软件里会动的按钮会让人误以为机器在动。

红色只有一处。急停是全界面唯一使用「实心红 + 警示图标」的按钮，位于右栏底部最后一行，永不被滚动、永不被遮挡、永不与其它按钮同色。停止按钮用 Danger 描边（中性白底），避免与急停抢注意力。

输入字段

圆角外壳 + 无边框内控件。这样做的原因很实际：WinForms 原生 NumericUpDown 在 125% / 150% DPI 下会把 1px 边框画成 2px 斜切凸起，而外壳是自绘的，永远 1px 6px 圆角，且所有字段左边缘严格对齐。

06状态机

这一节是整套设计的核心。红色不是装饰，是权限：下面这张表决定每个状态下哪些控件可用、哪些变灰。

固件状态显示颜色允许界面反应
Idle待机 Idle绿全部常态
Run书写中 Run蓝 · 呼吸暂停 / 停止 / 倍率画布出十字笔位；底部出进度条；左栏编辑区收成锁定条；开始书写变灰
Jog移动中 Jog琥珀停止Jog 键保持高亮，其它动作暂灰
Hold:0 / 1已暂停 Hold琥珀继续 / 停止进度条转琥珀；继续提为主按钮
Alarm报警 Alarm红解锁 $X / 软复位画布上方出红色横幅并内嵌两个动作；Jog 全部变灰；状态条圆点变红
Door门开 Door红解锁同 Alarm，文案换成「安全门已打开」
Home归零中 Home蓝停止DRO 数值变灰并显示 —，避免误读中间值
Sleep休眠 Sleep灰复位唤醒胶囊变灰并提示「点任意处唤醒」
—未连接灰连接Jog、主操作、急停全部变灰；DRO 保留上次读数并转灰
报警横幅的原则：错误信息、原因、出路三者必须在同一屏内。ALARM 1 只告诉用户「硬限位」，用户还得去别处找怎么解锁——所以横幅右侧直接放「解锁 $X」与「软复位」。这是 GRBL 客户端长期缺失的一环。

07键盘映射

Jog 面板把方向键画在屏幕上，是为了让键盘映射可被发现——每个方向键下方都印着对应的键名。这一条来自对 CNС 老手的观察：他们从不点方向键，只用键盘。

08易用性与可达性

触达尺寸Jog 键 40×40，主按钮高 36，最小可点控件 26×26。低于这个尺寸在 125% DPI 的笔电上会点空。
焦点可见键盘焦点用 2px #185FA5 外描边 + 2px 偏移，不复用悬停态。Tab 序严格按视觉顺序：左 → 中 → 右。
不靠颜色单独表意状态胶囊同时有文字、圆点、底色三层编码；报警除了红还有三角图标与文字原因。
错误预防停止与急停都要二次确认；$X 解锁只在 Alarm 下出现；导出前若未生成，按钮直接变灰而不是弹错。
空态即引导没文稿时画布不是空白，而是三个入口（打开 / 粘贴 / 快捷键），把「下一步做什么」写在最显眼处。
数字不抖DRO 用等宽字体 + 固定列宽 + 右对齐，坐标变化时不会出现整行重排的闪烁。

09WinForms 实施映射

本方案按 .NET Framework 4.8 / C# 5 / 零外部依赖 的现有约束设计，全部可用自绘实现。下表是每一条视觉规格的落地方式与风险等级。

设计规格实现方式风险备注
圆角卡片 / 按钮GraphicsPath + FillPath（已有 FillRound）低抗锯齿用 SmoothingMode.AntiAlias
卡片投影不能真投影：1px 边框 + 底部 2px 渐变色带模拟中GDI+ 无模糊滤镜，别硬做
图标16×16 坐标系手绘 GraphicsPath，按 rect 缩放低不用图标字体，DPI 安全
等宽坐标Consolas 9.5pt + TextRenderer.DrawText 右对齐低禁用 Graphics.DrawString（字宽不准）
状态呼吸动画Timer 40ms 改圆点 alpha中只在 Run 时启动，Idle 停掉省 CPU
分段控件自绘 Panel + 命中测试换取选中索引低不要用 TabControl（见下）
输入框外壳Panel 画边框 + 内嵌 BorderStyle=None 真控件低所有字段左缘才能严格对齐
页签TabControl + DrawMode=OwnerDrawFixed + 双缓冲高绝不能开 UserPaint，否则页签与页面主体全部不绘制

自绘背景OnPaint 首句必须 UiPaint.Clear高UserPaint|AllPaintingInWmPaint 下框架不擦背景，会叠影
